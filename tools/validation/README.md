# Validation artifacts

`validation/profiles/hbm2_2000.json` and `hbm3_6400.json` are machine-readable profile contracts. They name the request format, organization, timing, mapping, each tool binding, and remaining non-equivalence. `generate_microtraces.py` creates deterministic semantic workloads and separately encodes them below `validation/traces/hbm2_2000/` and `validation/traces/hbm3_6400/`. `summarize_hbmsim.py` runs either profile and emits normalized completion and summary CSVs.

The GitHub Actions workflow converts the same neutral CSV sequence for Ramulator 2.1 and DRAMSys, runs all three tools, and uploads `validation/` as `hbm-validation-results`. The entry point is `validation/results/three-simulator-comparison.csv`; raw Ramulator JSON statistics, DRAMSys TDB databases/logs, converted inputs, and configuration metadata are kept beside it for audit.

V0.6.4 uses one 32 B pseudo-channel payload per request and profile-representable absolute arrivals. Both address encoders start from the same `(PseudoChannel, BankGroup, Bank, Row, Column)` tuple, preventing different flat-address mappings from silently changing a workload. The reference workflow applies `patch_ramulator_timed_trace.py` only to the pinned checkout: it preserves arrivals, waits for every read/write callback, and records per-request completion cycles. The comparison includes completion counts, mean/p50/p95 latency, throughput, ACT/PRE/RD/WR totals and row locality. The manifests record known model differences, so the results remain an auditable alignment baseline rather than a claim of bit-for-bit equivalence.

`assert_semantic_gate.py` verifies workload shape, physical-command/merge accounting, and exact per-request latency partitioning. `assert_numeric_regression.py` rejects HBMSim HBM2 drift from the frozen v0.6.4 result. `assert_reference_trends.py` requires finite metrics and shared row-hit/conflict/write-only trends in all runnable tools. `assert_h6_gate.py` verifies full request completion for all three HBM2 tools and both HBM3 tools. Cross-simulator latency equality is intentionally not required; the comparison tables expose model differences for review. DRAMSys HBM3 remains explicitly unsupported.
